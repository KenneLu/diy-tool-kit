# diy-tool-kit 文档索引

> 本目录是模板库的规范文档根目录。旧版综合规范保留在 `归档/`，只作历史参考；现行规范按“公共规范 + 工具类型”分层。

## 文档优先级

1. [公共规范](公共规范.md)：所有工具都必须满足的共性要求；
2. [工具类型](工具类型/) 下的类型文档：该类型工具的专属要求；
3. [归档/托盘工具工程规范-20261025.md](归档/托盘工具工程规范-20261025.md)：旧版综合参考，不再作为新工具的主判据；
4. 各模块 `README.md`：模块 API 与接入细节。

发生冲突时：**公共规范 > 工具类型规范 > 归档参考**；模块 README 只解释模块自身，不覆盖规范。根 README 与本节重复声明同一优先级。

## 工具类型

| 类型 | 适用 | 文档 |
|---|---|---|
| 托盘工具 | 常驻托盘、GUI、自启、更新器、服务/隧道 | [工具类型/托盘工具.md](工具类型/托盘工具.md) |
| 命令行工具 | 无托盘、按需运行、stdout/stdin、可打包 exe；不等于“只能从源码跑” | [工具类型/命令行工具.md](工具类型/命令行工具.md) |

一个工具只能选择一个主类型；同时具备多个类型特征时，选主类型，再在“类型差异表”里登记额外特征。HTTP MCP、SSH 隧道、无界面常驻服务等归为“服务型特征”，作为附加项登记，不单独复制第三套规范。

## 迁移与对照

- [迁移与工具对照](迁移与工具对照.md)：四个既有工具、旧规范迁移映射、类型差异/不采用登记表、迁移状态；
- 新工具架构验收必须逐项对照本表，不得只读规范。

## 公共规范覆盖什么

- 立项、分级、不采用项登记；
- 目录职责：`src/`、`tests/`、`resources/`、`scripts/`、`docs/`；
- 参数卡、模板借条、共享模块；
- 用户数据区、配置、日志；
- 双语 i18n；
- 构建门禁、测试、证据；
- 打包与发布布局（PyInstaller onedir 为默认）；
- Git、文档、脱敏、无绝对路径；
- 协作与复核方法。

## 新工具最低动作

1. 选择主类型；
2. 复制公共规范的“类型差异与不采用登记”表；
3. 按类型文档补齐差异；
4. 用公共规范 [附录 A](公共规范.md#附录-a新工具自检清单) 清单逐项自检；
5. 架构验收必须对照 [迁移与工具对照](迁移与工具对照.md) 中的四个既有工具，而不是只读规范。

## 与其他文档的关系

- `baseline/`：README/CHANGELOG/LICENSE/.gitignore 基线；
- `build_release/`：构建/发版脚手架；
