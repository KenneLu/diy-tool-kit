# 命令行工具规范（无托盘）

> 适用：无托盘、无 GUI、按需运行、以命令/参数/stdout/stderr 为主要交互的工具。
> 不代表“只能从源码运行”：最终用户应拿到打包 exe，不需要安装 Python。
> 公共要求见 `../公共规范.md`；冲突时公共规范优先。
>
> **范围限制**：四个既有工具（dsh-helper、local-speak2text、opencodex-helper、reme-helper）都是托盘类型，不能直接套用本文；HTTP MCP + SSH 隧道属于服务型/托盘型能力，不属于 CLI 默认形态。本文只适用于主类型明确为命令行工具的新工具。

## 1. 判定

满足以下条件时选此类型：

- 主要交互是命令行参数、配置文件、标准输入/输出；
- 不需要托盘图标、开机自启、常驻窗口；
- 不需要托盘菜单或设置窗口；
- 不依赖本地 GUI 事件循环；
- 可在命令结束后退出。

同时具备托盘/GUI 能力时，按主类型“托盘工具”处理，并在类型差异表登记 CLI 例外。

## 2. 进程生命周期

- 一次调用执行一个命令或一个批处理任务，结束即退出；
- 不得隐藏常驻后台进程；
- 需要长期协议服务时，明确使用 stdio 服务模式（如 MCP），由客户端保持连接；
- stdio 服务不是端口监听、不是托盘、不是系统服务；
- 程序退出码必须表达结果：
  - `0` 成功；
  - 非 `0` 失败，并在 stderr 或报告中给出可定位原因；
- 不允许“打印成功但实际失败”的假绿。

## 3. CLI 契约

必须有稳定的命令面和帮助：

```text
<tool> --help
<tool> --version
<tool> <command> [options]
```

要求：

- 子命令语义稳定，变更要记录；
- 参数解析失败返回非 0；
- 输出默认写 stdout，错误写 stderr；
- 机器可读结果（JSON 报告）与人类提示分开；
- 路径参数必须可显式指定，并有默认发现规则；
- 相对输出路径相对项目解析，且必须落在项目约定输出目录（例如 `.render/`）内；不得静默写到工具当前工作目录；
- 破坏性操作需要显式参数或确认；
- 不在帮助/错误信息中泄露本机绝对路径；`%CD%` 等运行时派生路径可用于构建，但不得硬编码个人目录；

## 4. 打包与交付

### 4.1 默认交付

- PyInstaller **onedir**；
- `--console`，因为需要命令行输出；
- 目标机器不需要 Python；
- exe 在 release 根目录；
- `_internal/` 自带 Python 运行时；
- `docs/`、`skills/`（如有）随包分发；
- 源码运行只用于开发和重建。

```text
release/<name>-<version>/
  <name>.exe
  _internal/
  docs/
  skills/                 # 如需要
  config.example.json
  README.md
  README.zh-CN.md
  CHANGELOG.md
  LICENSE
```

### 4.2 验证

构建门禁至少包含：

1. 单元测试；
2. 源码命令冒烟；
3. PyInstaller onedir；
4. 发布目录内容检查（exe、`_internal`、docs、skills（如有）、无 tests/samples/用户配置）；
5. 冻结 exe 的命令冒烟；
6. 无 Python 环境冒烟（目标 PATH 不含 Python，仍可运行）。

不能用“源码能跑”代替“exe 能跑”。

### 4.3 `run.bat`

- `run.bat` 只是源码便利包装，不是最终用户入口；
- `run.bat <args>`：执行一次 CLI 命令后退出；
- `run.bat mcp`（如有）：启动 stdio 协议服务，客户端保持输入连接时才存活；
- 文档必须说明它是一次性命令还是协议服务，避免用户误以为常驻。

## 5. 用户数据、项目数据与输出

- 用户配置/日志在 `%LOCALAPPDATA%\<APP_ID>\`（或平台等价目录）；
- 项目数据在工具安装目录之外的独立项目文件夹；
- 项目标记、数据文件、生成物位置在 README 中说明；
- 生成物只写项目内约定目录或显式输出路径；
- 不得在工具安装目录写项目数据或临时数据；
- 支持多个项目时，使用显式 `--project` 或明确默认发现规则；多候选必须报错，不得猜。

## 6. 模型上下文协议（可选）

如果工具提供 MCP：

- 使用标准输入/输出，不监听端口；
- 客户端启动子进程，输入关闭后退出；
- 不要求托盘、系统服务或自启；
- 工具/提示词/资源清单要稳定，并登记版本；
- 工具参数必须能定位项目；
- 服务端只声明能力边界，不把外部浏览器/设计平台能力冒充为本工具能力；
- 需要常驻浏览器的方案属于外部编排，不是本工具的默认实现。

**范围**：HTTP MCP、SSH 隧道、常驻服务属于托盘/服务型特征，不属于本节；有这类能力时需在类型差异表登记，并按对应类型文档处理。

## 7. 测试与验收

### 7.1 自动测试

- 命令解析、成功路径、错误路径；
- 数据/资产校验负例；
- 确定性输出；
- 输出边界与项目隔离；
- 并发/锁冲突；
- 打包 exe 冒烟。

### 7.2 功能验收

- 用户用真实项目或真实数据跑主流程；
- 真实浏览器打开生成物；
- 真实客户端验证 MCP（若提供）；
- 用户确认可用，不以测试全绿代替；
- 证据包含命令、退出码、产物指纹、真实点击记录。

### 7.3 不应要求用户做的事

- 不要求用户安装 Python（最终用户路径）；
- 不要求用户改工具源码；
- 不要求用户使用托盘/服务；
- 不要求用户读内部实现才能使用。

## 8. 已知反例

- 只给源码，要求用户配 Python 环境；
- 只测源码，不测冻结 exe；
- exe 套一层目录，和其他工具布局不一致；
- 文档写“双击 exe → 托盘/端口/常驻服务”，实际没有；
- 把 stdio MCP 写成局域网端口服务；
- 把生成物写入工具安装目录；
- 文档出现固定盘符的绝对路径或个人目录；
- 测试全绿就宣布用户功能验收通过。

## 9. 检查清单

- [ ] 主类型是“命令行工具”；
- [ ] 命令帮助/版本/退出码稳定；
- [ ] stdout 与 stderr 分离；
- [ ] PyInstaller onedir，`--console`；
- [ ] exe 在 release 根目录；
- [ ] `_internal` 自带运行时；
- [ ] 无 Python 环境冒烟通过；
- [ ] 发布目录 docs/skills（如有）随包；
- [ ] 源码运行只作开发方式；
- [ ] `run.bat` 的行为已说明；
- [ ] 项目数据在工具目录外；
- [ ] 生成物只在项目约定目录；
- [ ] 文档无绝对路径/敏感信息；
- [ ] MCP（如有）为 stdio，无端口/无托盘；
- [ ] 真实项目验收与自动测试分开。
