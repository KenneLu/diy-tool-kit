# 托盘工具规范

> 适用：常驻托盘、GUI、开机自启、更新器、本地服务或 SSH 隧道的工具。
> 公共要求见 `../公共规范.md`；冲突时公共规范优先。
> 旧版综合规范保留在 `../归档/托盘工具工程规范-20261025.md`，只作完整参考。

## 1. 判定

满足任一主要特征时选此类型：

- 常驻托盘图标或窗口；
- 需要托盘菜单、设置窗口、状态页；
- 需要开机自启、单实例、更新器；
- 需要本地服务、SSH 隧道、常驻浏览器会话；
- 有 GUI 事件循环和用户交互窗口。

如果同时有 CLI，CLI 是辅助入口，不是主类型。

## 2. 进程与生命周期

- 默认单实例；重复启动应唤起已有实例或明确拒绝；
- 退出、重启、停止服务必须有明确路径；
- 托盘图标是生命周期入口，不能与后台进程状态脱节；
- 关闭窗口不等于退出程序，需在文档中说明；
- `--quit` 等非交互退出参数必须可靠；
- 进程退出时必须清理自己拥有的资源，但不误杀用户/其他工具的资源；
- 更新器、服务、隧道必须有“链路不可用 ≠ 用户拒绝”的三态处理。

## 3. 托盘与 GUI

- 使用模板 `tray_kit` / `tray_icons` 或同等的公共层，避免每个工具各写一套；
- 图标、任务栏图标、状态图标通过 `icons` / `tray_icons` 生成和加载；
- 菜单项、双击行为、设置窗口入口要稳定；
- 设置窗口只在配置项超过 8 个或菜单承载不了时引入；
- 有 GUI 时统一主题、深色模式、双语、窗口生命周期；
- 不允许把托盘线程和业务线程混在一起；公共模块已有线程模型时不要绕开。

## 4. 自启、更新、服务、隧道

这些是托盘类型的高频能力，但全部按触发条件接入：

| 能力 | 触发条件 | 模板模块 |
|---|---|---|
| 开机自启 | 托盘常驻工具 | `autostart` |
| 更新检查/自动更新 | 有远端仓库 + 第二台机器/长期维护 | `update_helper`（必须跑 `ota_test` 本地验收） |
| 服务唯一性/接入/清理 | 工具管理本地服务 | `service_link` |
| SSH 隧道 | 工具需要远程连接 | `tunnel_kit` |
| 图标生成 | 需要 ico/托盘状态图 | `icons` / `tray_icons` |

不采用时按公共规范 §1.1 登记原因。

## 5. 打包与交付

- PyInstaller **onedir**；
- `--noconsole`（GUI/托盘工具不弹控制台）；
- exe 在 release 根目录，`_internal` 自带 Python 运行时；
- **命名与版本（公共规范 §7.1）**：安装目录、exe 名、发布 zip 内层目录都不带版本号；
  版本写进 exe 的 PE 文件属性（`--version-file`）；发布 zip 内层为稳定 `<APP_ID>/`；
- 图标、任务栏图标、`locales/`、`resources/` 随包；
- 文档在 `docs/`，运行时可读文档按工具约定随包；
- 发布目录不含样例、测试、用户配置。

## 6. 验证

- 构建门禁：测试、图标检查、PyInstaller、冻结 exe 冒烟；
- 托盘启动/退出/重启；
- 菜单项、设置窗口、双击行为；
- 自启注册/注销；
- 更新检查、下载、替换、回滚；
- 服务唯一性、接入、清理；
- 隧道启动/停止/自愈；
- 双语文案；
- 真实用户操作验收，不以测试全绿代替。

## 7. 检查清单

- [ ] 主类型是“托盘工具”；
- [ ] 单实例与退出路径可靠；
- [ ] 托盘/菜单/图标状态一致；
- [ ] 自启、更新、服务、隧道均按触发条件接入或登记不采用；
- [ ] `--noconsole`；
- [ ] exe 在 release 根目录；
- [ ] 安装目录/exe/zip 内层目录无版本号，exe PE `FileVersion` == 版本号；
- [ ] 有更新链的工具已跑模板 `ota_test` 本地验收、发布 zip 过 OTA 布局门禁；
- [ ] 冻结 exe 冒烟；
- [ ] 图标/本地化/文档随包；
- [ ] 真实用户验收。
